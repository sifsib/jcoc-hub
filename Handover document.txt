This document serves as the comprehensive engineering handover for the unified Kereke Hub ecosystem. It contains all architectural structures, system configurations, color codes, and database patterns required for a smooth transition to an incoming developer or AI collaborator.

1. Project Overview & Separation of Concerns
The ecosystem is built as a unified church administration platform split across two distinct Next.js applications sharing a single backend database instance.

kerekehub.co.za (Kereke Marketing Website): A multi-page Next.js front-end focused entirely on high-conversion leads, channel metrics, support ticketing, and onboarding workflows. It acts as the public visitor center.

hub.kerekehub.co.za (Kereke Hub Core Application): The secure, multi-tenant administrative engine where verified church staff manage data, generate rosters, and parse financials.

Both systems are built on an identical engineering engine—utilizing Next.js, TypeScript, Tailwind CSS, and Firebase. They share the exact same Firebase production database instance, allowing marketing data and support tickets to feed straight into active platform administration backends.

3. Database Architecture & Production Schema
The platform relies on an enterprise-grade multi-tenant model mapped within Cloud Firestore. Complete data isolation is strictly enforced at the database layer using a distinct tenantId structural pattern.

Key Production Collections Matrix
tenants: Tracks registered organizations, subdomains, payment states, and workspace profile criteria.

users: Houses user profiles, email descriptors, and Role-Based Access Control (RBAC) tokens (e.g., Admin, Staff, Volunteer).

members: Stores deep membership details, cross-generational family nesting fields (Spouse, Parents, In-Laws), and critical faith milestones.

attendance: Captures regular service metrics and cell-group tracking indexes.

support_tickets: Automatically logs inbound engineering assistance records pushed from the marketing domain interface.

demo_requests: Indexes walkthrough registrations from prospective church leaders.

4. Advanced System Features & Functionalities
The architecture has been designed around specific structural modules customized for local, cost-sensitive church environments:

Tiered Core Analytics: Evaluates running weekend and cell assembly attendance profiles to identify alignment trends and automatically flag sudden membership drop-offs.

Secure Financial Ledger: Allows leaders to track localized contributions against budgeting goals. Includes a built-in function to export datasets cleanly into CSV format for easy external bank statement audits, as well as an upload attachment option to capture supporting receipt photos at the exact point of entry.

Per-Tenant Custom Branding: Enables individual organizations to input their own unique church name and primary brand color accent to override system display frames dynamically.

Gmail SMTP Cloud Routing: Bypasses expensive global transactional mail layers by allowing individual churches to plug in their own official Gmail SMTP credentials. Automated member notifications, statements, and outreach are processed through a backend Firebase Cloud Function triggered on update metrics.

API Route Isolation (v1 Pipeline)

6. Business Funnel & PayFast Logic
The monetization strategy focuses heavily on rapid adoption for small churches by eliminating automated sign-up friction:

Manual Trial Validation: Users submit their information on the marketing site. After a live tour, an administrator issues a manual code.

Payment Bypass Onboarding: Pastors type their 30-day code into the sign-up form at hub.kerekehub.co.za/register. This creates their isolated database workspace without forcing credit card capture up front.

PayFast Step-Billing Tokenization: On Day 31, users are restricted by a soft wall prompting payment authorization. Due to the custom pricing structure (Month 1 Free, Months 2–4 at R99 p/m, and Standard Month 5+ at R139 p/m), you must implement PayFast Tokenization instead of a fixed standard subscription. This allows the backend to securely pass explicit step-up charge values to PayFast over time using a single authorized transaction token.
